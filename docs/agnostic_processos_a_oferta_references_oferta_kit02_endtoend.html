Estructures NO obvies (descúbertes per prova)

hallazgos.json — evidencia[].fuente ha de ser SRC-### del procesos.json → fuentes.ficha (ex. SRC-012), MAI SRC-VEN-01. cita literal del camp (reescrit-la llegint la fitxa, no teclejant-la). categoria dins la llista tancada. Cada dolor d'un node → 1 hallazgo (referenciat nodos:[<id>] + cita_ref:"CODI#<id>.dolor").

to-be/.json — còpia de la fitxa as-is amb: estado:"Propuesta pendiente de validación", node problemàtic canviat a nom "després" + propuesta:"AUT-XXX" (i esborrar el dolor), + camp cambios[] amb {tipo:"automatizado", nodo, antes, despues, automatizacion} per cada node canviat. L'esquema de to-be és la fitxa ficha-proceso/1 (no té .schema.json propi).

escandallo.json — {schema, estado:"estimacion_interna", aprobado_por:null, elementos:[{id, horas:{consultoria,desarrollo,integracion,pruebas,documentacion,formacion,despliegue,estabilizacion}, externos_eur, contingencia_pct, justificacion_contingencia, notas}]}. horas és un objecte lliure (cap esquema intern). complexitat diferenciada per integració (TPV > agenda > CRM senzill).

oferta.json — {schema, referencia, titulo, vigencia_dias, incluidas[], futuras[], base{modo, precio_eur}, extras[], descuentos[], procesos_sin_to_be, resumen_ejecutivo{objetivos[], propuesta_recomendada}, fases[], responsabilidades_cliente[], requisitos_cliente[], limites_servicio[], siguientes_pasos[], meses_facturables_primer_ano, inicio_facturacion_texto, ahorro_monetario}. Els camps base, resumen_ejecutivo, incluidas, futuras són obligatoris.

equipo / herramientas del diagnostico-fase1.json → llistes d'OBJECTES ({rol,personas}, {nombre,categoria,uso}), no strings; la radiografia els llegeix amb .get().

Regla de comptatge → contradiccions

L'importador compara p1.pasos.length (resum) vs nodes tipo:"tarea" vs tasques BPMN. Les decisions (tipo:"decidir") són gateways, NO tasques: exclou-les dels pasos del resum. Cada procés ha de tenir un node fin (els que el motor trobava sense fin → "bucle sin salida"). Si el JSON BPMN propi no té pas fin als últims, l'adaptador n'afegeix un.

Bloquejadors d'oferta "llesta per signar" (NO tocar, decisió d'SPAI)

  • config/tarifas.json amb precio_implantacion i cuota.base_mensual a null → oferta BORRADOR, tots els imports "pendiente".
  • config/prestador.json razon_social/nif a null → no es pot declarar "llesta per signar".
  • Correcte deixar-ho com a borrador + dir-ho a Josep; MAI inventar números ni dades legals.

Scripts reutilitzables (quedaran a /opt/data/scripts/)

  • converteix-mataro-kit01.py — JSON BPMN propi → fitxes ficha-proceso/1 + diagnostico-fase1.json
  • gen_automatizaciones_mataro.py, gen_tobe_mataro.py, gen_escandallo_mataro.py, gen_oferta_mataro.py — generadors d'anàlisi (valors d'exemple de la perruqueria; adaptar).
