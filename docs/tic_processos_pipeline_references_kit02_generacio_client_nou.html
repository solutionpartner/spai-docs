El generador d'anàlisi (patró; els 6 fitxers els fa l'analista, no l'importador)

generar.mjs NO crea areas/hallazgos/automatizaciones/to-be/escandallo/oferta. Model de dades: - 1 hallazgo = 1 node amb dolor a la fitxa AS IS (llegir el dolor de modelo/fichas-as-is/<PROC>.json, NO del formulari — cites literals). - 1 AUT = 1 capacitat que resol els dolors d'un procés (pot ser 1 AUT per procés, o 2+ si els dolors són independents).

Campos OBLIGATORIS de cada fitxer (errors reals trobats a la validació del supermercat):

automatizaciones.json

  • Top-level per AUT: id (AUT-XXX-01), process_ids, finding_ids, analysis_status:candidata, viabilidad:viable_por_verificar, madurez_analisis:analizada, prioridad (1-5), prioridad_explicacion (>=10 chars), fase, depende_de, client (title/benefit/description/team_keeps_doing/out_of_scope/human_approval/acceptance_criteria/data_journey), internal, baseline (estado:pendiente + casos_mes/actividades/futuro), assumptions, source_refs, i recomanat implementation_price_eur:null, price_source:'escandallo', cuenta_en_cuota:true.
  • internal REQUEREIX: pattern (enum VÀLID: organizativo, configuracion_software, determinista, workflow_ia, rag_documental, agente, integracion_api, importacion_supervisada, rpa — NO hi ha "asistencia_ia"), escalera (objecte amb simplificacion/configuracion/determinista/asistencia_ia/agente), autonomy ('prepara_borrador'), ai_fallback, systems (llista), dependencias, i opcionals candidate_orchestrator:null, mcp_required:false, risks.

hallazgos.json

  • evidencia[].fuente HA de ser ^SRC-[0-9]{3}$ (SRC-001, SRC-002... progressiu per procés — no "SRC-0FUL-02").
  • categoria dins l'enum: transcripcion, datos_incompletos, duplicados, esperas, cambios_de_manos, trazabilidad, documentos_dispersos, notificaciones, conciliacion, seguimiento, errores, dependencia_persona, control_necesario, otro (no "proceso_manual").
  • cita = el dolor LITERAL de la fitxa AS IS; cita_ref = "PROC#node.dolor".

areas.json

  • REQUEREIX clau pendientes: [] (a més de schema:'areas/1' + procesos[] amb codigo/primary_business_area_id/related_area_ids/justificacion/estado:'confirmada'/pregunta:null).

to-be/.json

  • estado HA de ser EXACTAMENT "Propuesta pendiente de validación" (no heretar el de l'AS IS).
  • Cada node millorat porta propuesta: "AUT-XXX-01" DINS del node (com la clínica). Si la propuesta va en un camp superior (ex. propuesta_aut), el validador avisa "ningún paso está marcado como propuesta" i l'oferta no pinta els canvis en blau. Esborrar el camp superior.
  • cambios[] amb antes != despues per node (descripcions curtes: nom TO BE < 50 chars).

Verificació del PDF de l'oferta — FALS NEGATIU per línies primes (clau!)

Els BPMN del kit es dibuixen amb línies d'1,5px. Rendering amb pypdfium2 a escala baixa (0.3-1.5) amb llindar <235/<220 marca les làmines de procés com a "0,0% tinta al centre" — FALS NEGATIU: el diagrama hi és, però les línies primes no arriben al llindar a baixa escala. No confiar-hi per decidir que el PDF està buit.

Mètode fiable (el que diu la skill): PyMuPDF get_drawings() per pàgina — cada làmina AS IS/TO BE ha de tenir desenes de dibuixos vectorials:

import pymupdf
doc = pymupdf.open(pdf)
for i, pg in enumerate(doc):
    if "Cómo se trabaja hoy" in pg.get_text() or "Propuesta" in pg.get_text():
        n = len(pg.get_drawings())
        print(f"p{i+1}: {n} dibuixos")  # esperat: 20-47+ per làmina, no 0

Instal·lació (els venvs no tenen pip; usar uv amb python absolut):

uv pip install --python /opt/data/.claude/audit-system/.venv/bin/python pymupdf

Alternativa sense instal·lar res: pypdfium2 render a scale=4.0 amb llindar <245 mesurant la REGIÓ central (30-75% alçada) — línies primes SÍ apareixen (0.5-0.7% tinta, centenars de columnes amb traça) però la lectura és més ambigua que get_drawings().
